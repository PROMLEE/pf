# 메리츠 잔고 불러오기

2026-10-22. **계좌 관리 → 메리츠 계좌 연결 → 잔고 불러오기**에서 사용합니다.

## 사용 순서

1. 계좌 관리에 API를 신청한 메리츠 Super365 계좌를 등록합니다.
2. 잔고 불러오기에서 같은 계좌를 선택합니다.
3. 원화·달러 현금을 반영하려면 기존 현금 자산을 선택합니다. 기본은 현금 반영 안 함입니다. 계좌 미지정 현금도 명시적으로 선택하면 해당 계좌에 연결합니다.
4. 조회 후 수량·주당 평균 매입단가·현금의 변경 전후를 확인하고 반영할 항목을 선택합니다.
5. 확인 체크 후 **선택한 N건 반영**을 누릅니다. 조회와 취소만으로는 자산을 변경하지 않습니다.

- 현금은 증감액을 더하는 대신 조회 잔고로 교체합니다. 원화는 **D+2 예수금**, USD는 **추정 외화 예수금**이며 출금 가능 잔고와 다를 수 있습니다.
- 종목 ID·직접 배정·후보 규칙·기존 매입환율을 유지합니다. 기존 원화 매입단가는 기존 매입환율×새 외화 평단으로 계산합니다. 새로운 해외 종목의 과거 환율은 추정하지 않습니다. 이후 자산 수정에서 매입환율을 입력하세요.
- 보유수량·평단이 달라진 기존 종목은 수정, 없는 종목은 신규 등록합니다. 신규 종목은 기존 코드 배정 규칙을 사용하며, 규칙이 없으면 미분류입니다.
- API에 없는 종목은 자동 삭제·0주 처리하지 않습니다. 지원하지 않는 상품·통화·대출 잔고·중복 잔고 구분 및 소수점 6자리를 초과한 해외 수량은 경고와 함께 제외합니다.
- 주식·현금 변경을 하나의 DB 트랜잭션으로 처리하고 평가액 기록을 남깁니다. 거래 이력이나 입출금 내역을 역산하지 않습니다. 진행 중인 리밸런싱 거래는 자동 완료 처리하지 않습니다.
- 미리보기는 5분 동안 유효하며, 그사이 대상 계좌의 보유 정보나 현금이 바뀌면 재조회가 필요합니다. 중복 반영도 같은 검사로 차단합니다. 시세 갱신만으로는 미리보기가 무효화되지 않습니다.

## 서버 환경변수

```dotenv
MERITZ_APP_KEY=
MERITZ_APP_SECRET=
MERITZ_USER_ID=
# 필요한 경우에만, 실제 호출 단말의 12자리 MAC. 임의 값을 만들어 넣지 않습니다.
# MERITZ_MAC_ADDRESS=
```

현재는 **서버에 등록한 단일 계좌 / 지정 사용자 전용 연결**입니다. 일반 사용자가 관리자 메리츠 잔고를 조회하거나 반영할 수 없습니다. `MERITZ_USER_ID`는 API 계좌 소유자의 포트리듬 사용자 ID로 지정하며 브라우저에 노출하지 않습니다. 여러 사용자별 키 등록·계좌 자동 식별 기능은 제공하지 않습니다. 대상 계좌를 사용자가 직접 확인해야 합니다.

Vercel에도 키·소유자 환경변수를 별도로 등록하고 재배포해야 합니다. 로컬 연결 성공은 Vercel의 MAC 정책·연결 성공을 의미하지 않습니다. 실제 서버리스 호출 검증은 별도입니다. 주식 시세 공급자는 KIS를 유지합니다.

## 보안·인증

- 계좌·예수금 조회 4개 경로만 허용하며 주문·환전은 호출하지 않습니다.
- 세션 소유자·동일 출처·대상 계좌·현금의 소유권 및 통화를 검증합니다.
- 미리보기는 사용자·대상 계좌·변경 내용·만료 시각을 서버 HMAC으로 서명합니다. 반영 API는 브라우저가 보낸 임의 수량·평단을 저장하지 않습니다.
- 기존 비공개 `portfolio.market_data_tokens`에 메리츠 전용 식별자와 AES-GCM 암호문으로 토큰을 재사용합니다. 발급은 advisory lock으로 직렬화합니다. 실제 토큰 응답의 만료 시간을 사용합니다.
- 키·원본 계좌 응답·토큰을 클라이언트나 로그에 출력하지 않습니다.
- DB 스키마 변경은 없습니다. 기존 private RLS와 서버 소유권 검증을 유지합니다.

공식 자료: [API 명세](https://github.com/meritz-securities/open-api), [호출 예제](https://openapi.imeritz.com/samplecode-py).

## 이번 검증

- 실제 메리츠 API와 실제 보유 정보를 이용한 **미리보기 조회 성공**. 실제 사용자 자산은 변경하지 않았습니다.
- 자동 회귀 테스트 274개 통과. 소유자·출처·서명·만료·입력 검증 포함.
- 별도 GUEST QA 데이터로 실제 PostgreSQL 저장 후 전체 롤백: 신규·수정 종목과 현금 동시 반영, 기존 포트 배정·매입환율 유지, 중간 오류 전체 롤백, 중복 반영·변경 후 반영 차단, 토큰 재사용 확인.
- 합성 응답을 사용한 실제 브라우저에서 미리보기·선택 해제·확인 전 버튼 비활성·선택 2건 반영 완료·390px 모바일 배치 확인. 실제 계좌 저장과는 구분합니다.
- 보안 advisor에 WARN/ERROR 없음. 기존 private 테이블의 정책 없음 INFO는 서버 전용 접근 구조입니다.
