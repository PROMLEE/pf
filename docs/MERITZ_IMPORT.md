# 메리츠 잔고 불러오기

2026-10-22. 상단 **동기화** 버튼과 **계좌 관리 → 메리츠 계좌 연결**에서 사용합니다.

## 자동 동기화 · 2026-10-22 추가

내 Super365 계좌 및 기존 원화·달러 예수금 항목을 연결하고 자동 동기화를 활성화했습니다.

- 로그인 후 페이지 접속 시 **1회**, 이후에는 상단 **동기화** 버튼을 누를 때 실제 잔고를 조회하고 바로 반영합니다. 주기 조회나 브라우저 복귀 시 재동기화는 하지 않습니다.
- 원화는 D+2 예수금, 달러는 추정 외화 예수금을 사용합니다. 시세는 계속 KIS로 갱신합니다.
- 보유 수량·평단·현금은 최종 잔고로 교체합니다. 거래 차액을 다시 더하지 않으므로 반복 조회로 자산이 증가하지 않습니다. 메리츠에서 거래한 수량과 현금은 따로 수동 입력할 필요가 없습니다.
- **자동 동기화에서는** 전체 잔고 조회가 성공하고 해석 제외 항목이 없을 때, 완전히 매도해 목록에서 사라진 종목을 보유 목록에서 제외합니다. 지원 제외·부분 조회·네트워크 오류가 있으면 전체 자동 반영을 보류하고 기존 자산을 유지합니다.
- 계좌 관리에서 연결·연결 해제가 가능합니다. 연결 해제는 등록 자산을 삭제하지 않습니다. 연결된 현금을 삭제하려면 먼저 연결을 해제합니다.
- 편집·저장 중이거나 브라우저가 숨겨져 있으면 이 브라우저의 자동 요청·화면 반영을 보류합니다. 첫 자동 동기화가 보류된 경우 편집 종료 후 한 번 실행합니다. 다른 기기에서 이미 처리된 변경은 서버의 자산 충돌 검사 대상입니다.
- 서버의 사용자별 90초 유효 임대 잠금과 최근 시도 시각으로 여러 탭·기기·서버 인스턴스가 중복 조회·반영하지 않게 합니다. 오류 시 60초 재시도 간격을 둡니다. 서버가 강제 종료되더라도 임대 잠금이 만료되어 다시 시도할 수 있습니다. 변경이 없으면 자산·평가액 기록을 다시 저장하지 않습니다.
- 실제 계좌 소유자의 `MERITZ_USER_ID`와 키 해시가 일치해야 동작합니다. 다른 사용자에게는 기능이 표시되지 않으며 API 접근도 거부됩니다. 키를 다른 계좌 것으로 바꾸면 연결을 다시 설정해야 합니다.
- 예수금 연결과 마지막 성공 시각은 비공개 `portfolio.meritz_sync`에 보관합니다. 키·토큰을 이 테이블에 저장하지 않습니다. 현금 FK는 자산 수정의 삭제·재삽입 트랜잭션을 위해 커밋 시 검사합니다.
- 진행 중인 리밸런싱 계획의 거래 완료 표시는 자동 처리하지 않습니다. 잔고 차이만으로 개별 주문 체결을 역산하지 않습니다.

마이그레이션: `supabase/migrations/20261022101018_meritz_auto_sync.sql`. 운영 DB 적용 완료. Vercel에는 아래 메리츠 환경변수가 등록돼 있어야 합니다. Vercel 실행 환경의 연결 여부는 별도 검증 대상입니다.

## 사용 방법

- 로그인한 뒤 페이지를 처음 열 때 한 번 동기화합니다. 이후에는 상단 **동기화** 버튼으로 바로 반영합니다.
- 주기 조회, 탭 전환·브라우저 복귀 후 재조회는 하지 않습니다. 확인 체크·변경 목록 검토도 필요하지 않습니다.
- 최초 연결만 계좌 관리에서 Super365 계좌와 기존 원화·달러 현금 자산을 선택합니다. 연결 후 바로 반영합니다.
- 보유 수량·평단·예수금은 조회된 실제 잔고로 교체합니다. 기존 포트 배정과 매입환율을 유지하며 다른 계좌·가상자산은 변경하지 않습니다.
- 새 해외 종목의 과거 매입환율은 추정하지 않습니다. 필요한 경우 자산 수정에서 입력하세요.
- 진행 중인 리밸런싱 계획의 거래 완료 표시는 별도로 입력합니다.
- 기존 서명 미리보기 API는 호환성을 위해 서버에 유지하지만 사용자 화면에서는 사용하지 않습니다.

## 서버 환경변수

```dotenv
MERITZ_APP_KEY=
MERITZ_APP_SECRET=
MERITZ_USER_ID=
# 필요한 경우에만, 실제 호출 단말의 12자리 MAC. 임의 값을 만들어 넣지 않습니다.
# MERITZ_MAC_ADDRESS=
```

현재는 **서버에 등록한 단일 계좌 / 지정 사용자 전용 연결**입니다. 일반 사용자가 관리자 메리츠 잔고를 조회하거나 반영할 수 없습니다. `MERITZ_USER_ID`는 API 계좌 소유자의 포트리듬 사용자 ID로 지정하며 브라우저에 노출하지 않습니다. 여러 사용자별 키 등록·계좌 자동 식별 기능은 제공하지 않습니다. 대상 계좌를 사용자가 직접 확인해야 합니다.

Vercel에도 키·소유자 환경변수를 별도로 등록하고 재배포해야 합니다. 로컬 연결 성공은 Vercel의 MAC 정책·연결 성공을 의미하지 않습니다. 실제 서버리스 호출 검증은 별도입니다. 주식 시세 공급자는 KIS를 유지합니다.

## 보안·인증

- 계좌·예수금 조회 4개 경로만 허용하며 주문·환전은 호출하지 않습니다.
- 세션 소유자·동일 출처·대상 계좌·현금의 소유권 및 통화를 검증합니다.
- 미리보기는 사용자·대상 계좌·변경 내용·만료 시각을 서버 HMAC으로 서명합니다. 반영 API는 브라우저가 보낸 임의 수량·평단을 저장하지 않습니다.
- 기존 비공개 `portfolio.market_data_tokens`에 메리츠 전용 식별자와 AES-GCM 암호문으로 토큰을 재사용합니다. 발급은 advisory lock으로 직렬화합니다. 실제 토큰 응답의 만료 시간을 사용합니다.
- 키·원본 계좌 응답·토큰을 클라이언트나 로그에 출력하지 않습니다.
- 자동 동기화 설정 테이블만 추가했으며, 기존 자산 테이블과 private RLS·서버 소유권 검증은 유지합니다.

공식 자료: [API 명세](https://github.com/meritz-securities/open-api), [호출 예제](https://openapi.imeritz.com/samplecode-py).

## 기존 구현 검증 이력

- 실제 메리츠 API의 미리보기 조회에 이어, 사용자 요청에 따라 Super365 보유 잔고·예수금 자동 동기화를 켜고 첫 변경 8건을 반영했습니다. 다른 증권 계좌·그 외 현금·가상자산은 변경되지 않은 것을 확인했습니다.
- 자동 회귀 테스트 278개 통과. 소유자·출처·서명·만료·입력 검증 포함.
- 별도 GUEST QA 데이터로 실제 PostgreSQL 저장 후 전체 롤백: 자동 동기화, 서버 호출 간격, 일시 중지·재개, 부분 실패 시 기존 잔고 보존, 완전 매도 제외, 현금 FK 검사, 신규·수정 종목과 현금 동시 반영, 기존 포트 배정·매입환율 유지, 중간 오류 전체 롤백, 중복 반영·변경 후 반영 차단, 토큰 재사용 확인.
- 합성 응답을 사용한 실제 브라우저에서 미리보기·선택 해제·확인 전 버튼 비활성·선택 2건 반영 완료·390px 모바일 배치 확인. 실제 계좌 저장과는 구분합니다.
- 보안 advisor에 WARN/ERROR 없음. 기존 private 테이블의 정책 없음 INFO는 서버 전용 접근 구조입니다.

```bash
cd apps/web
node --test tests/*.test.mjs
PF_MERITZ_DB_TEST=1 pnpm dlx tsx tests/meritz-import.integration.mts
pnpm exec tsc --noEmit
pnpm build
```

- 자동 동기화 브라우저 검증: 합성 잔고 2→3주 자동 반영, 입력 중 변경 보류(화면 3주 유지), 입력 종료·복귀 후 4주 반영, 일시 중지·재개를 확인했습니다. 390px 모바일 화면에서 관리 버튼 배치도 확인했습니다. 실제 주문을 실행한 검증은 아닙니다.

## 동기화 단순화

30초 폴링·복귀 재조회를 제거하고 접속 시 1회 + 수동 버튼으로 변경했습니다. 입력 중 최초 동기화는 입력 종료 후 한 번 실행합니다. 자동 요청 실패 시 반복 재시도하지 않으며 동기화 버튼으로 다시 시도합니다.

## 연동 자산 직접 수정 제한

- 연결된 메리츠 계좌의 주식과 원화·달러 예수금은 읽기 전용입니다. 수량·평단·매입환율·잔고·이름 수정, 삭제, 수기·캡처 추가, 계좌 이동 및 현금 이체 입력을 차단합니다.
- 수정 화면과 계좌 관리에는 ‘메리츠 연동’ 표시를 보여 줍니다. 서버에서도 같은 제한을 검사하며 동기화만 실제 계좌 잔고를 반영합니다.
- 포트 배정은 앱 내 분류이므로 계속 변경할 수 있습니다. 환율 갱신에 따른 원화 환산액 변화도 허용합니다.
- 다른 계좌의 현금·가상자산은 자산 수정 목록에서 선택하면 별도 수정 창에서 개별 저장합니다. 이름·보유 금액·평균 환전 단가 또는 코인 수량·평균 매입단가를 수정할 수 있습니다.
- 검증: 자동 테스트 282개, 폐기 가능한 QA 계정의 PostgreSQL 트랜잭션에서 직접 수정·삭제·계좌 이동·신규 등록·현금 변경·이체 차단 확인 후 전체 롤백. 합성 데이터 브라우저에서 현금 저장·달러·코인 수정 창·메리츠 읽기 전용 및 390px 모바일 배치를 확인했습니다. 실제 사용자 자산은 수정하지 않았습니다.
