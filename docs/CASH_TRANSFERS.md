# 현금 이체 기록

## 이용 방법

1. 계좌 관리의 **현금 관리·이체**, 또는 **자산 수정 → 현금 이체 기록**을 엽니다.
2. 현금 자산별 **연결 계좌**를 선택해 저장하면 증권사·계좌명으로 구분할 수 있습니다. 계좌 미연결 자산도 이용할 수 있습니다.
3. 출금 현금과 동일 통화의 입금 현금을 선택합니다. 현금·RP로 관리하는 자산을 선택하세요.
4. 금액과 선택 메모를 입력하고 **이체 내용 확인 → 이체 기록 확정**을 누릅니다.
5. 두 잔액과 최근 이체 기록을 확인합니다.

원화는 1원, 달러는 소수점 둘째 자리까지 입력합니다. 원화↔달러 환전, 실제 송금, 수수료 자동 반영은 제공하지 않습니다. 잘못 입력한 내역은 반대 방향의 이체를 새로 기록해 잔액을 되돌릴 수 있습니다. 기록 시각은 앱에서 확정한 시각입니다.

## 계산

- 출금 잔액에서 금액 차감, 입금 잔액에 같은 금액 가산
- 같은 통화 총액 보존, 외부 입출금 내역 생성 안 함
- 포트가 다르면 포트별 비중은 변경
- 달러는 출금 자산의 기존 평균 환전 원가를 이동하고, 입금 자산 원가와 가중평균
- 출금 원가가 미확인이거나 입금 잔액의 원가가 미확인이면 합친 원가는 미확인(확인된 손익 집계 범위가 달라질 수 있음)
- 잔액은 DB 소수 단위를 보존하며, JS 부동소수점 덧셈으로 잔액을 계산하지 않음

## 저장·보호

`portfolio.cash_transfers`는 비공개 스키마의 서버 전용 테이블로 RLS가 켜져 있고 PUBLIC·anon·authenticated 직접 권한은 없습니다. 모든 조회·수정은 로그인 사용자 소유 자산으로 제한합니다. 현금 자산의 계좌 연결은 `(user_id, account_id)` 복합 외래키로 소유권을 보호합니다.

이체 API는 같은 출처 POST만 허용합니다. 사용자 포트폴리오 잠금 후 두 잔액·달러 원가·이체 기록·자산 기록을 하나의 트랜잭션으로 저장합니다. 중간 오류는 전체 롤백합니다. 같은 요청 ID의 재시도는 잔액을 다시 바꾸지 않습니다. 같은 ID에 다른 내용이면 거절합니다.

`cash_revision`은 현금 이체, 현금을 반영하는 주식 거래와 포트폴리오 저장에서 갱신합니다. 오래된 전체 자산 저장이나 다른 탭의 이체 요청은 충돌로 거절합니다. 충돌 시 최신 잔액·기록을 확인한 뒤 다시 입력합니다.

최근 이체 조회는 사용자별 최신 30건입니다. 이름·계좌명이 나중에 바뀌거나 자산이 삭제되어도 당시 표시 이름을 보존합니다.

## 검증

- 단위·API: `node --test tests/cash-transfer.test.mjs` (apps/web에서 실행)
- 실제 PostgreSQL 왕복: `node scripts/verify-cash-transfers.mjs`

DB 검증 스크립트는 `.env.local`의 연결과 GUEST인 로컬 QA 사용자만 사용합니다. 전용 테스트 자산으로 실행하고 잔액·원가·중복·소유권·통화·이전 저장 충돌·오류 원자성을 확인한 뒤 외부 트랜잭션을 항상 롤백합니다. 실제 사용자 보유 자산은 수정하지 않습니다.
