# 공지 푸시 알림과 홈 화면 설치

## 사용자 설정

**설정 → 알림·앱 설치 → 알림 켜기**를 누르고 브라우저 알림 권한을 허용합니다. 권한 요청은 이 버튼을 누를 때만 표시합니다. 첫 방문에 자동으로 권한을 요청하지 않습니다.

알림은 기기·브라우저별로 설정합니다. **테스트 알림 보내기**로 연결을 확인할 수 있으며 테스트는 같은 기기에 1분에 한 번만 허용합니다. 운영체제의 집중 모드·알림 차단·네트워크 때문에 도착이 늦거나 화면에 나타나지 않을 수 있습니다.

- PC·Android: 지원 브라우저에서 알림 권한을 허용합니다. 제공되는 설치 버튼 또는 브라우저 메뉴로 홈 화면에 설치할 수 있습니다.
- iPhone·iPad: iOS/iPadOS 16.4 이상에서 Safari 공유 메뉴 → 홈 화면에 추가 후 설치한 앱으로 열고 알림을 켭니다.
- 알림을 누르면 로그인 후 공지사항 화면에서 해당 공지 본문이 열립니다. 게시가 종료된 공지는 확인 불가 안내를 보여줍니다.
- 알림 끄기는 서버 구독을 비활성화합니다. 로그아웃은 해당 브라우저의 구독도 해제합니다. 실패한 네트워크 요청이 있더라도 브라우저 구독 해제를 시도합니다.

서비스 워커는 푸시 표시·알림 클릭만 처리합니다. 개인 자산·API 응답을 오프라인 캐시에 저장하지 않으며 오프라인 자산 조회를 제공하지 않습니다.

## 관리자 발송

**운영 관리 → 공지 작성/수정 → 게시 → 푸시 알림도 보내기 → 공지 저장** 순서로 요청합니다.

- 초안·게시 종료 상태에서는 새 알림 요청을 선택할 수 없습니다.
- 공지마다 발송 요청을 한 번만 등록합니다. 기존 요청이 있는 공지를 수정한다고 자동으로 다시 발송하지 않습니다.
- 예약 공지는 게시 시각이 지난 후 처리합니다. 첫 처리 시점에 활성화된 구독 기기를 대상으로 발송 대상을 확정합니다. 이후 구독한 기기에는 지난 공지를 발송하지 않습니다.
- 발송 대기 중 공지를 게시 종료하거나 기기 알림을 끄면 남은 발송을 건너뜁니다. 이미 전달된 알림을 회수하지는 못합니다.
- 알림 내용은 서비스명과 공지 제목입니다. 개인 자산 금액·보유 종목은 넣지 않습니다.
- 공지 목록의 발송 성공은 푸시 제공자가 수락한 건수입니다. 사용자의 실제 도착·열람 확인은 아닙니다.

## 서버 구성

### 키

VAPID 공개·비밀 키와 예약 호출용 비밀 값은 **Supabase Vault**에 저장합니다. 기존 서버의 DB 연결로 읽으므로 새 Vercel 환경 변수나 다른 Vercel 계정 접속은 필요하지 않습니다. API는 VAPID 공개 키만 브라우저에 전달합니다.

운영자 초기 설정 명령:

```sh
cd apps/web
node scripts/setup-push.mjs
```

기존 `.env.local`의 `DATABASE_URL`로 연결합니다. 이미 있는 키는 보존하며 비밀 값을 출력하지 않습니다. 잘못된 일부 키만 존재하면 자동 교체하지 않고 오류로 중단합니다. 키를 임의로 교체하면 기존 브라우저 구독이 더 이상 작동하지 않을 수 있습니다.

### 예약·재시도

Supabase `pg_cron`의 **portrhythm-push-dispatch** 작업이 매분 대기열을 확인합니다. 처리할 항목이 있을 때만 `pg_net`으로 `https://pf.promleeblog.com/api/push/dispatch`를 호출합니다. Vault의 비밀 값으로 인증하며 클라이언트나 일반 사용자는 호출할 수 없습니다. Vercel 자체 Cron은 사용하지 않습니다.

즉시 게시 요청은 Next.js `after`에서 첫 처리를 시도합니다. 실패하거나 남은 항목이 있으면 예약 작업이 이어받습니다. 한 호출당 최대 20개 기기, 5개씩 병렬 처리합니다. 발송량이 많으면 여러 분에 걸칠 수 있습니다.

각 기기의 발송에는 2분 처리 임대를 적용합니다. 제공자가 일시 오류를 반환하면 간격을 늘려 최대 5회 시도하며, 404/410 만료 구독은 비활성화합니다. 제공자 수락 직후 서버가 중단되는 경우에는 재시도될 수 있으므로 같은 알림 태그로 중복 표시를 줄입니다. 정확한 한 번 전달이나 정확한 시각 도착을 보장하지 않습니다.

### 접근 권한

- `portfolio.push_subscriptions`, `push_campaigns`, `push_deliveries`: RLS 활성화, `PUBLIC`·`anon`·`authenticated` 직접 접근 금지
- 구독 등록·해제·테스트: 서버 세션 사용자 범위, 동일 출처 검사, 기기 수 제한
- 등록 기기 제한은 활성 기기 10개이며 등록 시 사용자별 잠금으로 동시 요청을 직렬화합니다.
- 발송 주소는 알려진 Chrome/Firefox/Apple/Windows HTTPS 푸시 호스트만 허용합니다. 임의 내부망 URL로 발송하지 않습니다.
- 새로 설치한 `net`·`cron` 스키마는 공개 역할의 직접 실행·테이블 접근을 금지합니다.

## 확인과 한계

2026-10-14 검증:

- 자동 테스트: 권한·출처·소유권·발송 주소, 공개 키 응답, 테스트 제한, 공지 발송 요청 원자성, 재시도·만료 구독, 서비스 워커 클릭 범위
- 실제 DB: 게시 예정·기간 종료 제외, 반복 발송 대상 선점 차단, 테스트 자료 롤백
- 로컬 화면: 모바일 알림 설정, 게시 공지에서만 발송 선택 활성화
- 실제 기기의 권한 허용·알림 도착과 iOS 물리 기기는 검증하지 않았습니다. 배포 후 자신의 기기에서 테스트 알림으로 확인하세요.

참고: [Apple Web Push](https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers), [Supabase Cron](https://supabase.com/docs/guides/cron).
