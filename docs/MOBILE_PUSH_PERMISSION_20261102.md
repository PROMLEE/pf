# 모바일 알림 권한 상태 안내 보완

2026-11-02. 안드로이드 웨일에서 사이트·휴대폰 설정에 차단이 없는데도 ‘브라우저 설정에서 알림 차단을 해제해 주세요’가 나타난 사례를 기준으로 보완했다.

## 확인한 문제

기존 화면은 `Notification.permission === 'denied'`를 곧바로 사용자의 수동 차단으로 설명하고 버튼을 비활성화했다. 설정에서 돌아온 뒤에도 마운트 시 읽은 권한 값이 그대로 남았다. 브라우저가 반환한 권한 상태만으로 차단 원인이 사이트 설정인지 운영체제 앱 권한인지 브라우저 정책인지 확정할 수는 없다.

## 변경

- 사용자 차단으로 단정하는 문구를 제거하고 권한을 사용할 수 없는 현재 상태로 표시.
- 비활성 버튼 대신 **권한 다시 확인** 제공. 앱으로 복귀하거나 탭이 다시 보일 때 현재 권한·설치·지원 상태를 다시 읽음. 서버 조회·시세 조회를 반복하는 타이머는 추가하지 않음.
- 안드로이드에서는 사이트 권한과 휴대폰의 해당 브라우저 앱 알림 권한을 각각 안내. 웨일은 일반 브라우저로 구분하며 아이폰 전용 홈 화면 설치 조건을 적용하지 않음.
- 보안 연결, 프레임, 아이폰 홈 화면 실행, 앱 내부 브라우저, 기능 미지원과 권한 사용 불가를 구분.
- PushManager 전역 생성자뿐 아니라 ServiceWorkerRegistration의 pushManager 지원도 감지.
- 접힌 **알림 상태 확인**에서 브라우저·실행 방식·웹 푸시 기능·권한 값·기기 연결 여부 확인. 사용자에게 인증키·구독 endpoint를 노출하지 않음.
- 권한 요청은 사용자가 알림 켜기를 누른 동작에서만 실행. 권한을 우회하거나 사용 불가 상태를 허용으로 위장하지 않음.

## 검증과 한계

안드로이드 웨일 구분, denied→granted 재확인, 아이폰 설치 조건, iframe·내부 브라우저·미지원·HTTPS 조건 검사 추가. 자동 테스트 309개·타입 검사·프로덕션 빌드(35개 페이지)·diff 검사가 통과했다.

실제 사용자의 안드로이드 웨일 단말에서 원인이 확인되거나 알림 수신까지 해결됐다는 뜻은 아니다. 배포 후 ‘알림 상태 확인’의 값과 실제 기기 권한을 함께 대조해야 한다. Work 브라우저 사용이 비활성화되어 이번에 실제 기기 UI·알림 권한 창·수신을 직접 검증하지 못했다.

## 공식 자료

- [Chromium 권한 검사와 요청](https://chromium.googlesource.com/chromium/src/+/HEAD/components/permissions/README.md): 브라우저 정책·요청 억제·안드로이드 앱 알림 권한 확인.
- [웨일 공식 Google Play 안내](https://play.google.com/store/apps/details?id=com.naver.whale): 웹사이트·페이지 공유 알림에 사용하는 알림 권한 안내.
- [WebKit의 iOS·iPadOS Web Push 안내](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/): 홈 화면 웹 앱과 사용자 동작에서의 권한 요청.

## 후속: 버튼의 실제 동작 구분

‘권한 다시 확인’은 클릭될 때 같은 권한 값을 다시 읽기만 했고, 결과 문구도 화면 아래에 나타나 눌리지 않는 것처럼 보였다. 일반 브라우저의 안전한 실행 환경에서는 이제 상단 **알림 권한 요청** 버튼이 사용자 클릭 안에서 실제 `Notification.requestPermission()`을 호출한다. 이미 허용 상태라면 권한 창을 재요청하지 않고 기기를 연결한다. 브라우저가 거절하면 거절 결과를 버튼 바로 아래에 표시한다.

별도의 **상태 다시 확인**은 요청 없이 현재 상태만 읽고, 확인 횟수·한국 시간·권한 결과를 가까이 표시한다. iOS 설치 전·프레임·미지원 환경에서는 권한 요청을 강행하지 않는다. 브라우저가 denied를 반환하면 이를 허용으로 바꾸거나 구독 API로 우회하지 않는다. 실제 안드로이드 웨일의 권한 창이 열리거나 수신이 해결됐다는 검증은 아직 하지 못했다.

명시적 denied 재요청이 브라우저 API를 동기적으로 한 번 호출하고 그 결과를 그대로 지키는 회귀 검사를 추가했다.
