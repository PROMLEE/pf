# Android Whale 알림 미수신 진단

점검일: 2026-11-04 (KST). 앱 기준 커밋: `90f82b9`.

## 결론

현재 기기에서는 Google 서버의 발송 접수와 Android의 Whale 대상 메시지 브로드캐스트 전달까지 확인했다. 그러나 사이트 서비스 워커의 `push` 이벤트는 관찰되지 않았다. 현재 장애 지점은 **Whale의 네이티브 메시지 수신부터 사이트 서비스 워커로의 전달 사이**로 좁혀졌다. 내부의 어느 함수에서 중단되는지는 확인하지 못했다. Whale 전체 버전이 웹 푸시를 지원하지 않는다는 판정은 아니다.

발송 응답 HTTP 201은 Google의 접수 응답이며, 기기 알림 표시 성공을 의미하지 않는다.

## 점검 환경

- Samsung Galaxy S23 Ultra, Android 16
- Whale 4.1.0.18 / Chromium 138.0.7204.306
- 같은 기기의 Chrome 156.0.8078.79를 비교 대상으로 사용
- 실제 서비스: https://pf.promleeblog.com
- USB 원격 디버깅, 서비스 워커 이벤트 관찰, Android 브로드캐스트·알림 기록 확인

## 확인 결과

| 검사 | 결과 | 해석 |
| --- | --- | --- |
| Whale 알림 권한 | 허용 | 최초 권한 차단 문제와 현재 미수신 문제를 구분해야 한다. |
| 브라우저 VAPID 공개키와 서버 키 | 일치 | 다른 공개키로 생성한 구독을 사용하는 상황은 확인되지 않았다. |
| 브라우저 구독의 암호화 키와 저장된 키 | 일치 | 현재 구독의 키 저장 불일치는 확인되지 않았다. |

이번 세션에서 `com.google.android.c2dm.intent.RECEIVE`, 대상 `com.naver.whale` 브로드캐스트가 19:41:22, 19:41:30, 19:42:28 KST에 전달된 기록을 확인했다. 시험 발송 시각과 대응하지만, 메시지 본문·토큰을 추출해 식별하지 않았으므로 개별 암호문까지 대조한 결과는 아니다.

## 발송 호환성 비교

다음은 임시 시험 발송에만 적용했으며 저장된 구독 주소나 운영 발송 설정은 바꾸지 않았다.

| 비교 항목 | Google 응답 | Whale 표시 |
| --- | --- | --- |
| 기존 주소, 기본 암호화·일반 우선순위 | 201 | 미확인 |
| 높은 우선순위 | 201 | 미확인 |
| Topic 헤더 생략 | 201 | 미확인 |
| 구형 `aesgcm` 암호화 | 201 | 미확인 |
| 본문 없는 시험 push | 201 | push 이벤트 미관찰 |
| 공식 변경 이력의 staging·production 주소 형식으로 시험 | 201 | 미확인 |

발송 직후 및 후속 Android 알림 기록 확인에서 시험 알림이 없었다. 영구 미수신이나 모든 지연 가능성을 증명하는 결과는 아니다. 본문 없는 push도 도달하지 않아 암호화 방식만의 문제라는 가설은 뒷받침되지 않는다.

## 앞서 해결한 별도 문제

1. AdGuard의 Push API 차단으로 권한 요청이 즉시 거절되던 문제는 사이트 한정 예외 적용 후 권한 허용 및 Chrome 실제 수신으로 확인했다.
2. Whale이 발급한 `jmt17.google.com/fcm/send/…` 주소를 서버가 거부하던 문제는 정확한 호스트·경로만 허용하도록 수정했다. 구독 등록은 성공한다.

현재의 미수신을 위 두 문제의 미해결 상태로 설명해서는 안 된다.

## 아직 확인하지 못한 것

- Whale의 Firebase 수신 서비스에서 네이티브 GCM 드라이버로 전달되는 실제 내부 상태
- Android 작업 예약 또는 Whale 내부 메시지 분배·복호화 과정의 중단 여부
- 동일 버전의 다른 기기에서도 재현되는지 여부

관련 태그의 로그에서 원인을 특정할 오류는 얻지 못했다. 다른 앱의 Firebase 오류, 빈 GCM 내부 로그, 과거 포럼 신고는 이번 장애의 확정 근거로 사용하지 않는다.

## 후속 조치

Whale 측 재현에 필요한 최소 정보는 버전, 위 비교 결과, Android 전달 시각, 서비스 워커 미수신 결과다. 구독 주소 전체·토큰·암호화 키·VAPID 개인키는 공유하지 않는다. 외부 문의는 아직 보내지 않았다.

현재 사이트 코드만으로 해결됐다고 판단할 근거는 없다. 서버 접수 성공과 실제 기기 수신을 구분하는 진단을 유지하고, Whale 내부 구간을 확인할 수 있는 로그나 수정 버전에서 다시 검사해야 한다. 현재 검증된 비교 경로는 같은 기기의 Chrome이다.
