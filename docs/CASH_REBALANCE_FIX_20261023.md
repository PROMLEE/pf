# 현금 상세 수정·리밸런싱 현금 범위 보완

2026-10-23.

## 화면 변경

- 자산 수정의 공통 ‘저장됨’ 표시가 입출금·이체 영역 아래에 붙어 있던 문제를 제거했습니다. 추가 자산 등 미저장 변경이 있을 때만 관련 자산 영역에 저장 버튼이 나타납니다.
- 자산 수정 목록의 현금을 누르면 상세 화면으로 이동합니다. 상세의 ‘잔고 수정’을 펼쳐 이름·금액·연결 계좌·달러 평균 환전 단가를 수정하고 저장·취소할 수 있습니다.
- 입력 중 수정 영역을 닫으면 변경 폐기를 확인합니다. 자산 수정에서 상세로 들어갔다면 돌아가기·새로고침 후의 이전 화면 정보도 유지합니다.
- 연결된 메리츠 현금은 상세 열람만 가능하며 잔고 수정·삭제 제한을 유지합니다.

## 계산 원인과 변경

기존 계산은 허용 범위 안인 주식 포트를 자동 제안에서 제외했습니다. 이 때문에 여러 주식 포트가 목표보다 조금씩 부족하지만 모두 허용 범위 안이면, 초과 현금을 매수에 쓰지 않아 현금만 범위를 벗어날 수 있었습니다. 반대로 현금이 부족해도 범위 안인 포트의 초과분을 매도 후보로 검토하지 못하는 경로가 있었습니다.

이제 첫 제안의 모든 거래·추가 투입금을 반영한 **최종 현금 비중**을 다시 확인합니다. 범위 밖이면 기존 보유 정보를 기준으로 한 번 재계산하며, 범위 안인 다른 포트도 목표까지의 조정 후보로 검토합니다. 다음 조건을 지킵니다.

- 현금 목표와의 차이가 줄고 기존에 범위 안인 다른 포트가 범위를 벗어나지 않을 때만 보완 계산을 사용합니다.
- 사용자가 직접 선택한 종목·계좌, 매수·매도 제외, 후보 정책과 시세를 유지합니다.
- 신규 자금 모드에서 매도를 만들지 않습니다. 추가 자금·매도 대금·현금을 중복 합산하지 않습니다.
- 모든 포트가 이미 범위 안이면 기존처럼 기본 제안은 없습니다.
- 후보 부재·제외·가용 예산·주식 1주 단위 등으로 맞출 수 없으면 범위 밖 상태를 그대로 표시하고 안내합니다. 모든 경우를 반드시 맞춘다는 의미는 아닙니다.
- 이미 시작한 계획을 자동으로 다시 만들거나 실제 거래·잔고를 수정하지 않습니다. 새 계획 계산에 적용됩니다.

## 검증

회귀 검사는 현금만 초과한 경우, 현금만 부족한 경우, 추가 투입금·직접 선택·제외, 모두 범위 안인 경우, 살 수 없는 1주 가격을 포함합니다. 제안 수량을 실제 보유 수량에 반영해 재집계한 비중과 미리보기의 일치도 검사합니다.

실제 사용자 자산은 저장·수정하지 않았습니다. 이번 현금 상세 폼의 브라우저 저장 왕복과 물리 모바일 조작은 별도 검증이 필요합니다.

자동 테스트 287개, `pnpm exec tsc --noEmit`, `pnpm build`(33개 페이지 생성), `git diff --check`가 통과했습니다.
