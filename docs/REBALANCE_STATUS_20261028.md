# 현재 상태와 제안 이유 구분

2026-10-28.

## 문제

포트 자체는 허용 범위 안이어도 현금 비중 확보를 위해 매도 제안이 생길 수 있다. 기존 화면은 이를 모두 ‘매수·매도 제안’으로만 표시해서 어떤 포트가 실제로 범위 밖인지 구분하기 어려웠다. 현금이 부족할 때는 범위 안인 포트들을 목표까지 매도한 후 남은 돈으로 다른 범위 안인 포트를 매수하는 불필요한 조정도 발생했다.

## 변경

- 상단에 현재 범위 밖 포트의 개수·이름·부족/초과 방향 표시.
- 예상 비중 표에 현재→제안 후 비중, 현재 상태, 최종 범위 충족 여부, 목표와 실제 허용 범위를 함께 표시. 비교 비중은 소수점 둘째 자리까지 표시.
- 개별 포트에서 현재 상태와 제안 이유를 분리. 이유는 허용 범위 조정·추가금 반영 후 범위 조정·현금 비중 맞춤·직접 선택한 조정으로 구분.
- 현금 부족만 보완하기 위해 범위 안인 포트를 자동 매도할 때는 남은 현금 확보 필요액까지만 계산. 범위 밖인 포트의 조정과 사용자가 직접 선택한 거래는 이 제한으로 생략하지 않음.
- 모든 포트 목록과 종목 선택은 유지. 저장 잔고나 시작한 계획을 자동 수정하지 않음.

## 검증 범위

- 현재/최종 상태를 혼동하지 않는 표시 분류와, 현금 확보 후 불필요한 추가 매도·매수를 중단하는 계산 회귀 검사 추가.
- 자동 테스트 294개 통과, 타입 검사 통과. 프로덕션 빌드(33개 페이지 생성)와 `git diff --check` 통과.
- 메리츠 연결 소유자의 포트리듬 자료만 READ ONLY 트랜잭션으로 조회하고 롤백. 저장 가격·추가금 0원·기본 종목·제외 없음 기준의 수정 계산에서 최종 8/8 범위 이내를 확인. 운영 브라우저의 실시간 시세·직접 선택·제외 상태까지 동일하다고 단정하지 않음.
- Work 설정에서 로컬 브라우저 사용이 비활성화되어 변경 UI의 브라우저 시각 검증은 수행하지 못함. 실제 사용자 잔고와 계획 저장은 수행하지 않음.
