# 기능과 계산 기준

기준일: **2026-10-08**. 이 문서는 현재 코드와 화면의 동작을 설명합니다. 목표 비중과 예시 종목은 사용자가 정하며 앱이 투자 전략의 적합성을 판단하지 않습니다.

## 제품의 중심 흐름

**목표 설계 → 보유 자산 등록 → 자산 배정 → 비중 점검 → 리밸런싱 검토 → 기록**

포트폴리오는 사용자별로 하나의 계획을 관리하며, 그 안에 여러 사용자 정의 포트를 둡니다. 포트별 이름·색상·목표 비중과 전체 허용 오차를 저장합니다. 현재 별도의 여러 전략을 동시에 만들고 전환하는 기능은 없습니다.

증권사·거래소 계좌의 보유 수량 자동 동기화, 앱 안의 주문, 모든 증권사 화면 OCR, 자동 배당·세금 집계는 현재 제공하지 않습니다. 가상자산은 자동 거래 수량 제안보다 초과·부족 금액의 직접 검토를 지원합니다.

## 가격·환율의 출처와 갱신

| 데이터 | 출처 | 키와 동작 |
| --- | --- | --- |
| 국내·미국 종목 검색 | KIS 배포 종목 마스터 | 종목 마스터 검색 자체는 앱 키 없이 가능 |
| 주식 현재가·전일 종가 | 한국투자증권 Open API | 서버의 KIS 앱 키·시크릿 필요 |
| 가상자산 코드·가격·전일 종가 | 빗썸 공개 API | 공개 가격 조회는 계좌 토큰 불필요 |
| USD/KRW | Frankfurter를 통한 ECB 기준환율 | API 키 없이 조회, 일일 기준환율 |
| 주식 캡처 가격·수량·매입단가 | 사용자가 등록한 OCR 검토 결과 | 브라우저에서 인식 후 검토·저장 |

화면이 활성 상태일 때 주식은 약 5분, 가상자산은 약 1분 간격으로 갱신을 시도합니다. 요청·중복 조회 제어, 네트워크 상태와 외부 API 응답에 따라 지연될 수 있습니다. REST 조회이므로 모든 체결을 즉시 받는 실시간 스트리밍은 아닙니다.

자동 환율은 최대 한 시간 간격으로 갱신 여부를 확인합니다. ECB 기준환율은 일일 기준값으로 증권사 환전 호가와 같지 않습니다. 자동 조회를 기다리는 동안 마지막 저장 환율로 먼저 평가하며 직접 입력 모드도 제공합니다.

마지막 확인 가격·조회 시각과 일별 평가액은 초기 표시·기록을 위해 DB에 보관합니다. 현재가는 화면의 가격 갱신 경로를 통해 API로 조회합니다. 조회 실패 시 마지막 가격이나 주식 캡처 가격을 사용할 수 있으므로 출처와 기준 시각을 함께 읽어야 합니다. 전일 종가 응답은 화면에서 일간 손익 계산에 사용됩니다.

KIS 접근 토큰은 만료 전 재사용하며 비공개 DB 캐시에 암호화해 저장합니다. 인스턴스가 바뀌어도 기존 토큰을 찾아 사용하도록 구성돼 있습니다.

## 평가액

```text
국내 주식 평가액 = 보유 수량 × 평가 가격
미국 주식 원화 평가액 = 보유 수량 × USD 평가 가격 × 적용 USD/KRW
가상자산 평가액 = 보유 수량 × 빗썸 KRW 현재가
원화 직접 입력 자산 = 입력한 원화 금액
달러 직접 입력 자산 = 입력한 USD 금액 × 적용 USD/KRW
총 평가액 = 위 자산들의 원화 평가액 합계
```

주식의 평가 가격은 API 현재가를 우선하고, 없으면 캡처 가격을 사용합니다. 가격이 없으면 정확한 평가가 불가능하므로 가격 확인 상태를 함께 표시합니다. 보유 자산 화면은 국내 KRW와 미국 USD를 별도로 보여주고 대시보드는 원화로 합산합니다.

## 전체 손익

```text
종목 평가손익 = (평가 가격 − 평균 매입단가) × 현재 보유 수량
종목 수익률 = 평가손익 ÷ (평균 매입단가 × 현재 보유 수량) × 100
전체 수익률 = 집계 가능한 평가손익 합계 ÷ 해당 종목 매입금액 합계 × 100
```

미국 종목의 매입금액과 평가금액은 모두 현재 적용 환율로 환산합니다. 매수 당시 환율을 저장해 계산하는 별도 환차손익은 포함하지 않습니다. 매입단가·가격이 확인된 주식·가상자산만 집계하며 직접 입력 자산은 제외합니다. 실현손익, 배당, 수수료·세금이 포함된 총투자성과가 아닙니다.

대시보드에서 동일한 주식을 묶을 때는 **시장·거래소·종목코드**를 사용합니다. 매입단가가 모두 알려진 그룹의 평균 매입단가는 수량 가중평균입니다. 일부 계좌의 매입단가가 누락되면 그룹 손익을 완전한 값으로 표시하지 않습니다.

## 일간 손익

```text
종목 일간 손익 = (API 현재가 − 해당 시장 전일 종가) × 현재 보유 수량
종목 일간 수익률 = (API 현재가 − 전일 종가) ÷ 전일 종가 × 100
```

미국 종목은 결과를 현재 적용 환율로 원화 환산합니다. 집계되는 전체 일간 수익률은 확인 가능한 종목의 전일 평가액 합계를 기준으로 계산합니다. 전체 수익·일간 수익 전환은 요약과 종목 목록에 함께 적용됩니다.

이 값은 현재 보유 수량을 전일 종가와 비교한 참고값입니다. 당일 체결 시점, 매수·매도, 환율 변화, 현금, 입출금, 배당·세금은 별도로 계산하지 않습니다. 국내·미국·가상자산은 기준 시간과 시장이 다르며 동일한 한국 시간 하루의 실제 계좌 손익으로 볼 수 없습니다.

전일 종가가 없는 종목은 일간 손익을 계산하지 않습니다. 조회 중과 정보 없음 상태를 구분하고 집계 가능한 종목 수를 표시합니다.

## 포트 비중과 배정

```text
현재 비중 = 포트의 원화 평가액 ÷ 전체 원화 평가액 × 100
그래프의 차이 = 현재 비중 − 목표 비중
리밸런싱 조정 방향 = 목표 비중 − 현재 비중
```

주식의 직접 배정은 자동 규칙보다 우선합니다. 자동 규칙은 시장과 종목코드로 포트를 찾습니다. 직접 미분류로 지정한 항목도 수동 지정으로 취급하며, 자동 배정으로 되돌려야 규칙이 다시 적용됩니다. 가상자산과 직접 입력 자산은 각 항목의 포트를 사용합니다.

현금도 배정한 포트의 비중에 포함됩니다. 예를 들어 현금을 미국 지수 포트에 배정하면 실제 주식만의 비중보다 미국 지수 포트 전체 비중이 커집니다. 현금을 별도 포트로 관리할지 해당 포트의 대기 자금으로 볼지는 사용자가 정합니다.

원형 그래프는 현재 또는 목표 비중순으로 정렬하며, 마우스 이동·선택과 모바일 탭으로 상세 정보를 표시합니다.

## 리밸런싱

목표와 현재의 차이가 사용자의 허용 오차(%p)를 넘는 포트를 조정 대상으로 검토합니다. 미분류 자산이나 가격 미확인 종목이 있으면 제안 준비 상태를 확인해야 합니다.

| 방식 | 예산 기준 |
| --- | --- |
| 매도 후 매수 | 예상 주식 매도 대금 안에서 매수 수량 계산 |
| 신규 자금으로 매수 | 사용자가 입력한 신규 자금 한도 안에서 매수 수량 계산 |

보유 종목과 등록한 매수 후보를 기준으로 주식 1주 단위 수량을 계산합니다. 특정 종목은 이번 조정에서 제외할 수 있습니다. 정수 주 단위와 자금 한도 때문에 조정 후에도 차이가 남을 수 있습니다.

가상자산 조정은 초과·부족 금액의 직접 검토 항목으로 안내하며 주식 거래 미리보기에는 반영하지 않습니다. 계좌별 잔고·매매 가능 여부·수수료·세금·환전·실제 체결 가격을 반영하는 주문 시스템은 아닙니다.

## 기록

한국 날짜 기준 하루 한 평가액 기록을 관리합니다. 같은 날짜에 기록하면 최신 평가액으로 갱신하고 과거 날짜는 유지합니다. 저장·가격 갱신 등 평가액을 변경하는 작업과 **오늘 기록**에서 기록이 갱신될 수 있습니다.

```text
순입금 = 해당 기록 기간의 입금 합계 − 출금 합계
순입금 제외 증감 = 기간 끝 평가액 − 기간 시작 평가액 − 순입금
```

새 자산 등록·수량 수정·배당·수수료·환율 등의 영향을 모두 분리하지 않으므로 순입금 제외 증감은 참고용입니다. 장중 시세 히스토리, 시간가중 수익률, 금액가중 수익률은 현재 제공하지 않습니다.

## 데이터와 개인정보

잔고 이미지는 브라우저에서 Tesseract.js로 분석하며 앱 서버에 보내거나 저장하지 않습니다. 사용자가 확인한 종목 데이터는 계정에 저장합니다. 종목 아이콘은 외부 공개 이미지 출처를 사용할 수 있으며 로그인 자체는 소셜 제공자의 인증 흐름을 거칩니다.

NextAuth가 기존 사용자 ID를 식별하고 Next.js 서버가 사용자 범위를 제한해 비공개 PostgreSQL `portfolio` 스키마에 접근합니다. DB 연결 정보·KIS 비밀 키는 서버 환경 변수입니다. 소셜 제공자별 계정은 자동 병합하지 않으며, 계정 공유와 서로 다른 도메인의 로그인 세션 공유는 구분됩니다.
