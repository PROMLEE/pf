# 정기 포트폴리오 점검과 브라우저 알림

2026-11-02.

## 사용 방법

1. **설정 → 알림·앱 설치 → 브라우저 알림 켜기**로 이 기기의 수신을 허용합니다.
2. 같은 화면의 **점검일·리밸런싱 알림**에서 필요한 항목을 선택하고 저장합니다.
   - 월간 비중 점검: 매월 1~28일 중 선택.
   - 분기 말 점검: 3·6·9·12월 마지막 달력 날짜.
   - 허용 범위 이탈: 최근 앱에서 확인한 비중을 기준으로 최대 주 1회.
3. **리밸런싱** 상단에서 다음 점검일과 지난 점검일을 확인합니다. **오늘 점검 완료**는 확인 날짜만 기록하며 거래·잔고·진행 중인 계획은 바꾸지 않습니다.

모든 알림 종류는 기본 꺼짐입니다. 일정은 계정에 저장되며, 브라우저 알림 수신은 허용한 기기에서만 가능합니다. 기존 공지 알림은 유지합니다. 설치·권한·운영체제 절전 및 푸시 서비스 상태에 따라 실제 수신이 늦거나 누락될 수 있습니다.

한국 시간 오전 9시부터 순차 처리합니다. 점검을 오전 9시 전에 완료한 경우에도 같은 날 정기 점검을 다시 요청하지 않고 다음 기간으로 이동합니다. 분기 점검일은 거래소 개장일과 별개입니다.

## 범위 이탈 알림의 기준

접속 후 가격을 확인하고, 모든 자산의 가격·배정이 확인되며 미저장 포트 변경이 없을 때 비중을 점검합니다. 보유 주식·가상자산은 조회 시각이 최근 24시간 안인 경우만 사용합니다.

서버에는 시세나 평가액을 새로 저장하지 않습니다. 서버가 현재 사용자의 저장된 목표·허용 오차로 범위 이탈 여부를 판정하고, **이탈 여부와 확인 시각**만 보관합니다. 알림 본문에는 금액·보유 종목을 넣지 않습니다.

예약 작업은 최근 24시간 안에 확인한 결과만 사용하고, 같은 계정의 범위 이탈 알림을 최대 7일에 한 번 요청합니다. 최근 확인 결과가 없거나 범위 안으로 돌아왔거나 점검을 완료했다면 해당 알림을 보류합니다. **앱에 접속하지 않은 동안 실시간 시장을 감시하는 기능은 아닙니다.** 알림을 열면 최신 시세로 다시 판단해야 합니다.

## 운영 구조

- 기존 `portrhythm-push-dispatch` Supabase Cron과 Vault의 VAPID·발송 인증키를 재사용합니다. 새 Vercel 환경변수는 필요하지 않습니다.
- 기존 인증된 `/api/push/dispatch`에서 공지 발송 후 점검 큐를 처리합니다.
- `portfolio.review_preferences`: 사용자별 알림 종류·점검일·마지막 점검·확인 결과.
- `portfolio.review_deliveries`: 기간·기기별 중복 방지, 발송 상태, 최대 5회 재시도와 작업 임대.
- 같은 기간·기기의 중복 삽입을 차단하고, 발송 직전에 동의·기기 상태·만료·점검 완료를 다시 확인합니다. 외부 푸시 발송과 DB 기록은 하나의 트랜잭션이 될 수 없으므로 절대적인 exactly-once 전달을 보장하지는 않습니다. 알림 태그도 기간별로 고정합니다.
- 만료된 기기(404/410)는 비활성화합니다. 일시적 오류는 지수 간격으로 재시도합니다. 오래된 정기 알림은 7일 뒤 보류하며 무제한으로 누적 발송하지 않습니다.
- RLS를 켜고 `public`·`anon`·`authenticated` 직접 권한을 철회합니다. NextAuth 서버가 세션 사용자 ID로 모든 읽기·변경을 제한합니다. 클라이언트가 제출한 사용자 ID는 사용하지 않습니다.

마이그레이션: `supabase/migrations/20261102091533_portfolio_review_reminders.sql`. SQL을 연결된 프로젝트에 적용했고, 기존 발송 예약 작업 하나를 확장했습니다. 사용자 알림을 자동으로 켜거나 알림키를 교체하지 않았습니다.

- 프로덕션 빌드: 성공, 35개 페이지 생성. 전체 테스트 304개 통과. 타입 검사와 `git diff --check`도 통과했습니다.
- Work 설정에서 브라우저 사용이 비활성화되어 실제 기기의 권한 창·알림 수신·화면 배치는 이번에 검증하지 못했습니다.
